# capgemini-data-engineering-training
# 🔹 Phase 1 – From SQL Thinking to PySpark Thinking

## 🚀 Overview

In this phase, I moved from writing traditional SQL queries to understanding how similar operations are performed using PySpark. 

The focus was not just on syntax, but on changing the way I think about data processing — from query-based execution to a more programmatic approach.

---

## 🧩 Core Concepts Explored

I worked with PySpark DataFrames and learned how to perform essential operations such as:

- Extracting specific columns from datasets  
- Applying conditions to filter records  
- Grouping data to perform aggregations  
- Viewing and verifying outputs during each step  

This helped me understand how structured data can be manipulated efficiently using PySpark.

---

## 🔁 Bridging SQL and PySpark

Instead of memorizing syntax, I tried to relate each SQL operation to its PySpark equivalent:

- Retrieving data → handled through DataFrame column selection  
- Conditional filtering → applied using transformation functions  
- Group-based operations → performed using grouping mechanisms in PySpark  

This approach helped me gradually shift my mindset from SQL queries to PySpark transformations.

---

## 🛠️ Practical Work

To strengthen my understanding, I implemented small data tasks such as:

- Exploring complete datasets to understand structure  
- Applying filters to extract meaningful subsets  
- Working with conditions like age-based filtering  
- Performing grouped analysis

These exercises improved my confidence in handling real datasets.

---

## ⚡ Difficulties I Faced

- Adapting to PySpark syntax after being comfortable with SQL  
- Understanding why PySpark uses a different approach for grouping operations  
- Getting used to writing logic step-by-step instead of a single SQL query  

---

## 💡 What Changed in My Thinking

This phase made me realize that:

- PySpark is not just a replacement for SQL — it’s a different way of solving problems  
- Writing transformations step-by-step gives more control over data processing  
- Understanding concepts is more important than memorizing syntax  

---

## 🎯 Outcome

By the end of this phase, I was able to:

- Confidently perform basic data transformations using PySpark  
- Relate SQL logic to PySpark operations without confusion  
- Approach data problems with a clearer and more structured mindset  

This phase prepared me to move into more advanced topics like joins and complex transformations.
